# Замеры инференса (провайдеры)

Замеры сняты командой `python -m bench.bench --label …`, цифры лежат в runs/bench/*.json. Железо: MacBook Pro, 16 ГБ, LM Studio (Metal), контекст 8192.

| метка | стек | модель/квант | клиентов | TTFT p50/p95, с | ток/с | RAM/VRAM, ГБ |
|---|---|---|---|---|---|---|
| gemma4-e4b | LM Studio | google/gemma-4-e4b, 4 бита | 1 | 0.374 / 0.374 | 28.8 | 6.86 (веса, `lms ps`) |
| gemma4-e4b-c2 | LM Studio | google/gemma-4-e4b, 4 бита | 2 | 0.803 / 0.806 | 18.6 | 6.86 (веса, `lms ps`) |
| cloud | облако | не снято | | | | |

Память в таблице взята из `lms ps`, а не из bench: сервер LM Studio держит модель в отдельном процессе, и `bench` видит только оболочку приложения (0.07 ГБ).

## Параллельные клиенты

Память `M = W + KV + A + O`. Веса W = 6.86 ГБ. KV-кэш по ориентиру из задания 0.14 МБ/токен даёт около 1.15 ГБ на сессию в 8192 токена (оценка сверху, точный коэффициент для этой модели не измерялся). Под систему и активации оставляем около 5 ГБ из 16, на KV остаётся примерно 4 ГБ. Расчёт: до 3 параллельных клиентов.

Замер с двумя клиентами подтверждает, что память держит, но скорость на клиента падает с 28.8 до 18.6 ток/с, TTFT вырастает с 0.37 до 0.80 с. Три клиента не снимали.

## Вывод

Берём в работу google/gemma-4-e4b в 4 битах: она помещается в 16 ГБ с запасом на контекст и даёт около 29 ток/с с TTFT под 0.4 с на одном клиенте. Второй квант и облако пока не замерены, сравнение с облаком и выбор кванта добавим после снятия облачной строки.
